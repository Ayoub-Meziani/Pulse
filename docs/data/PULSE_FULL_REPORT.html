4.2 How the tables relate

  • One person = one login (auth.users) = one profiles row (role patient / doctor / admin). Patients have one patient_profiles row.
  • Every patient-owned table has patient_id → profiles.id. A doctor's access is never stored per row: it is computed from an active doctor_patient_assignments row by the helpers private.is_assigned_doctor() and private.is_admin().
  • Same-patient keys: a reading can only use the patient's own device; an alert can only attach the same patient's readings (alert_measurements, composite keys); ring samples can only come from the patient's own device.
  • Chains: measurements → alerts → alert_measurements; devices → wearable_samples → (monitor) → wearable_flags → band_id → patient_bands; patient_bands.supersedes_id and care_plans.supersedes_id keep history instead of overwriting.
  • History, never silent deletes: readings are append-only; wrong readings stay, flagged; changes to sensitive tables are copied to audit_log (old row, new row, actor).

5.1 How the BP simulator works (pulse_data/simulate.py)

Each synthetic patient has a baseline systolic (cohort: uniform 110–165 mmHg), a diastolic of about 0.62 × systolic, a slow trend, a chance of skipping a session, and (60 % of them) a medication with a chance of missing doses. Every day the generator draws the day's context, then a hidden BP effect:

effect(day) = latent drift + day noise + trend × day + 6 if a dose was missed yesterday + 1.2 × (sodium − 3,200 mg) / 1,000 − 2 if activity ≥ 30 min + 2 if sleep < 6 h
latent drift = φ × yesterday's drift + Normal(0, σ) · reading: systolic = baseline + effect + 4 (morning surge) + Normal(0, 5); diastolic = baseline + 0.55 × effect + 2 + Normal(0, 3.5), at least 15 below systolic; pulse ≈ Normal(72, 6), +3 in the morning.
Sessions around 07:00 and 20:00 (−40 to +60 min), 1–2 readings each; 0.3 % of readings have systolic and diastolic swapped on purpose, to test data cleaning.

The effects of missed doses, salt, activity and sleep are invented for testing the pipeline; they are not clinical estimates.

5.7 Data rules that hold everywhere

  • Every row says where it came from: source = manual / device_sync / csv_import / simulated; ML artefacts say synthetic:pulse-sim-v2 or real:nhanes.
  • Only valid readings feed averages, trends and ML; needs_review and invalid readings are counted, not used.
  • No health values in logs or error messages; jobs print counts only.
  • Raw real data never leaves the laptop; the demo password and the database URL live only in .env.

6.1 How every model is trained and tested (same recipe)

1. DataGenerate the labelled synthetic cohort, or load real data from data/external/
2. FeaturesSame code in training and serving (features.py, ring.night_table, week_examples)
3. Split by patient70 / 15 / 15, seed 7; no patient in two sets; features only from earlier days
4. CandidatesA simple model (ridge or logistic) vs gradient boosting
5. Choose on validationPick the best on validation patients only
6. Test onceOn unseen test patients, vs simple baselines; 95 % bootstrap CI over patients
7. Savemodel.joblib + metadata.json, versioned folder
8. ServeA batch job loads it and writes only its own table

Tests check the recipe: no patient overlap, no feature from the target day or later, deterministic retraining, and jobs that write only their own table.

6.2 mbp-v1.1: next-day morning blood pressure SERVED

Use
Informational estimate in the doctor's view, labelled "Model estimate (synthetic training data)". Never shown to patients, never used for alerts or medication.
Target
Mean systolic and diastolic of the next patient-local day's readings before 12:00.
Inputs (21 features)
From valid readings of the 7 days before only: last morning value, 7-day and 3-day means, 7-day morning mean, 7-day slopes, systolic spread, morning−evening gap, reading count, days with readings, day of week (7 flags).
Eligibility
≥ 6 valid readings on ≥ 4 local days in the 7 days before, and ≥ 1 morning reading; otherwise insufficient_history (no numbers).
Training data
pulse-sim-v2, 200 patients × 90 days (36,890 readings, seed 7).
Split
By patient: 140 / 30 / 30 patients → 8,730 / 1,918 / 1,929 patient-days.
Model choice
Validation MAE (mean of sys and dia): ridge 6.18 vs gradient boosting 6.30 → ridge.
Uncertainty
Split-conformal interval from validation patients: ±16.2 systolic / ±9.6 diastolic; on test it covered the true value 90.1 % / 89.5 % of the time (target 90 %).

6.3 ring-v1.1: ring monitoring FLAGS ONLY

Use
Advisory flags for the doctor, never an alert, never the safety path.
Night statistic
Median of each metric 00:00–06:00 local (HR, HRV, SpO2, skin temperature), built from raw wearable_samples by the same code in training and serving.
Flag 1: reference
SpO2 night median < 94 % (BTS; 88 % with COPD) or resting HR > 100 bpm (Mayo). Live 10-minute windows need ≥ 2 samples.
Flag 2: personal
Doctor-approved band if one exists; else robust z = (value − median) / (1.4826 × MAD) over the 28 nights before (≥ 14 nights, confirmed anomalies left out), flag if |z| > 3.5.
Flag 3: multivariate
IsolationForest on the 4 personal z-scores (contamination 0.01, a synthetic setting). Skipped with atrial fibrillation; HRV is never flagged with AF.
Training data

6.7 Real population "safe band" for the cuff pulse (NHANES)

How PULSE uses it: the weekly report places the patient's 7-day mean seated cuff pulse as a percentile among US adults of the same sex and age (summary.pulse_vs_population). It's context, not a threshold, and it is never applied to ring night HR (a different measurement). BP percentiles are also stored, but home BP categories use the ACC/AHA home column, because NHANES BP is exam BP.

11. Safety, ethics and limits

  • ML is advisory only. No model creates alerts, decides an emergency, or suggests starting, stopping or changing medication. Symptoms trigger the emergency path on their own.
  • Patients never see ML output until the backend owner and a clinician decide what a patient should see.
  • Synthetic is always labelled. Metrics on synthetic data show the pipeline works; they say nothing about real patients.
  • Not validated for Algeria. NHANES is the US population; Mendeley is one patient; Apnea-ECG is 8 lab nights.
  • Data terms respected: NHANES statistics only (no re-identification, no linkage); Mendeley non-commercial; PhysioNet attribution.
  • Before any real use: real, consented daily home readings; retraining and evaluation by patient and over time; clinician review of thresholds, wording and display; drift monitoring.
