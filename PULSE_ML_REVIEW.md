# ML review: model `mbp-v1` (branch `AI` @ `fcad8a2`)

Reviewed 2026-10-30 by reading `ml/pulse_ml/{features,train,predict}.py`, `ml/tests/test_ml.py`, `ml/artifacts/mbp-v1/metadata.json`, `ml/MODEL_CARD.md`, and by **re-running** the pipeline in an isolated copy (pinned `numpy 2.5.4, pandas 3.1.0, scikit-learn 1.9.1, joblib 1.6.0`).

## 1. Verdict

**Usable for the MVP as a clearly labelled, doctor-only "model estimate" and as evidence of a real, leakage-safe ML pipeline. Not clinically meaningful.** The model beats the 7-day-mean baseline by only 0.45 mmHg systolic on synthetic data and is statistically indistinguishable from it on diastolic. Pitch the pipeline and its honesty, not the accuracy.

## 3. Issues (non-blocking for the MVP)

1. `metadata.json` does not record the scikit-learn/numpy versions used; add them (pickles break across versions).
2. `features_until` is the start of the target day, not the time of the last reading used; document it or store the last reading time.
3. The interval is a constant width for every patient; say so in the doctor view ("±10 mmHg typical error"), not "confidence interval".
4. Diastolic gain over the 7-day mean is within noise; the doctor panel should show the 7-day mean beside the estimate.

## 4. Backend ↔ ML interface (binding)

| Item | Contract |
|---|---|
| Producer | Data/AI developer's batch job `pulse_ml.predict`, run with `DATABASE_URL` (privileged), after seeding/replay and before the demo; optionally daily. Never called from an API request. |
| Storage | `public.ml_predictions` (M4, live): `patient_id, target_date (patient-local date), target='morning_mean_bp', status ok|insufficient_history, predicted_systolic, predicted_diastolic (numeric 5,1; non-null iff ok), interval_{systolic,diastolic}_{low,high}, model_version, trained_on, features_until, n_readings_used, created_at`; unique `(patient_id, target_date, model_version)`; RLS: assigned doctor/admin read only. |
| Active model | Backend setting `PULSE_ML_MODEL_VERSION` (default `mbp-v1`); rows of other versions are ignored. |
| Backend read | `GET /api/v1/patients/{id}/predictions/latest` (doctor, active assignment; patient → 403): newest row for the patient and active model by `target_date desc, created_at desc`. |
| Mapping to `PredictionOut` | no row → `model_unavailable`, all values null; row with `target_date` before the patient's local today → `model_unavailable` (stale); `insufficient_history` → that status, values null; `ok` → `predicted_*` as float, `interval = {systolic: [low, high], diastolic: [low, high]}` when all four are non-null, `generated_at = created_at`, `model_version`, `trained_on`, fixed `limitations` text. |
| Isolation | The API imports no ML library; `api/pyproject.toml` stays free of numpy/pandas/scikit-learn. ML output never enters `analysis/rules.py`, alerts, measurements or any patient-facing response. If the table is empty or the job never ran, every API flow works unchanged. |
| Display | Doctor views only: "Estimation du modèle (données d'entraînement synthétiques)", value ± typical error, model version, next to the 7-day mean. |
